This check is for the people who volunteer a condition while asking for an accommodation, and for the managers later shown their standing preferences. We looked for a Salesforce tool published as "RAI Self Check Skill" in the provisioned org, on AgentExchange and among the Salesforce DX MCP server's fifteen toolsets, and couldn't find one. Rather than imply we ran one, we built the check ourselves against the published guidelines and say so.

So we ran the same exercise against Salesforce's five published guidelines for responsible agentic AI, as a harness anyone can run: python3 tests/rai_self_check.py. 21 checks across Accuracy, Safety, Honesty, Empowerment and Sustainability. 19 pass, 0 fail, 2 undecided. Undecided never counts as a pass. --selftest breaks five checks on purpose and asserts each goes red.

WHAT IT FOUND ON THE FIRST RUN

The seed file could no longer rebuild the deployed library. The agent may only name accommodations that a grounded Apex action returned from a sourced library. The org held 28 rows. The seed in the repository held 24. The four missing rows were the lighting ones added to fix an earlier bias defect, where "I get migraines from the office lighting" returned "special chair or back support" because the word office appeared in that summary.

So anyone deploying from our repository would have silently reintroduced the defect we fixed, and our claims about that fix would have been false on their org. The seed is now regenerated from the org, and a check compares the two on every run.

A FINDING WE WITHDREW

The same run failed a check asserting that every library row states a cost. Nine do not. But the code was already right: it renders a cost only when one is known, and otherwise says "I have no cost or precedent figure to give you. I will not estimate one." The check was too strict, so we corrected the check rather than the code, and recorded the coverage gap as undecided instead of quietly passing it. We say so here so nobody trusts a green that wasn't earned.

BIAS

The agent cannot improvise an accommodation, a cost, or a precedent count. Options come from a SOQL query over 28 individually sourced rows, and the ranker now weighs how much a word distinguishes rather than whether it merely appears. The migraine defect taught us that.

FAIRNESS

The system holds no protected attribute to be unfair with. There is no field for a diagnosis, condition, disability type, medical note, severity or prognosis in 61 fields across 9 objects. We didn't answer this by encrypting a diagnosis field: we never created one. Encryption defends against outsiders, and the adversary here is the organisation holding the data: a manager with legitimate access to an encrypted diagnosis field can still read it. A field that doesn't exist can't be read, leaked or subpoenaed. Volunteered conditions are stripped before the insert on the one write path every channel shares, and again on standing preferences, the text built to be shown to managers. Deaf, blind, hard of hearing, wheelchair user, autistic, ADHD and dyslexic are never stripped: those are identity, not medical detail.

TRANSPARENCY

Every delivery attempt lands in a ledger that holds a salted hash, never the message body. A person can send WHO and see everyone who has been shown a standing disclosure of theirs. OFF withdraws it immediately with no reason asked, because there's nowhere to record a reason, so nobody can be asked for one later. Consent has two locks: the Apex won't set the approval flag without approval passed through, and a validation rule blocks the insert. On the agent path both key off the approval the model passes, so the second lock guards against other writers, not the model's judgement.

THE LESSON WE WOULD PASS ON

We told the agent not to record a volunteered condition. It complied in its narration while the action stored the text. So everything safety-critical now runs in Apex, on every request, where the model's memory doesn't matter.
