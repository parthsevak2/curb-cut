Curb Cut · walkthrough

Eight people, one library.

Every step below is something the system actually does today. Nothing here is staged, and where a channel is not fully live it says so rather than pretending.

setup Before you start

Three things, once. Everything after this is the walkthrough itself.

  1. Open a private browser window. Not a normal one. Half the point is that none of this needs an account, and you want to see that with your own eyes rather than take my word for it.
  2. Have a terminal open in the project, for the channels that are not a web page. 
    cd ~/Downloads/curbcut_check
  3. Log in to the console in a second, ordinary window — you are going to want to see the other side of the desk in scenes 7 and 8. 
    sf org open -o curbcut
Maya contract designer, six weeks in web

Her hands have been bad for a month. She has no work email, no staff login, and no intention of telling an agency she has only just started with that anything is wrong.

  1. In the private window, open the front door. 
    https://orgfarm-7a04c62cb9.my.salesforce-sites.com/curbcut/ask
  2. Type what is hard, in her words — not a diagnosis, not a category: 
    I cannot type for long
  3. Read what comes back. Note the cost line under each option.
  4. Choose Speech-to-text software and press Draft a request.
  5. Read the draft. Then, deliberately, try to hedge — imagine replying “I guess so”. There is no button for that. The only way forward is Yes, send it.

What should land

She got a real answer before anyone knew her name. No login wall, no “nature of disability” field, no upload of a doctor's letter.

And the request did not leave until she said so. The code that creates it refuses to run without an explicit yes — a hedge is not agreement, and a test proves the refusal.

Maya, three months later new manager, same body web → any channel

She is tired of explaining herself to every new manager. She wants it said once. Then, in November, she wants it taken back — from her phone, on a bus, without logging in to anything.

  1. On the same page, scroll to the thing you would rather not repeat. Write it in her words: 
    I need captions on every call
  2. Choose Manager only and Always, then Remember this.
  3. A six-character code appears. Write it down. It is shown once.
  4. Now close the tab completely. Pretend months pass.
  5. Come back from somewhere that has never seen her — a text message. Replace ABC123 with her code: 
    sf api request rest "/services/apexrest/curbcut/v1/message/" \
  -o curbcut --method POST \
  --body '{"channel":"SMS","text":"WHO ABC123"}'
  6. Then turn it off from somewhere else again — Slack this time: 
    sf api request rest "/services/apexrest/curbcut/v1/message/" \
  -o curbcut --method POST \
  --body '{"channel":"Slack","text":"OFF ABC123"}'
  7. Run that last command a second time, and then once more with a made-up code like ZZZZZZ.

What should land

She set it on a web page and switched it off from a text message, on a service that holds no account, no password and no phone number for her. The code is the only thing connecting the two, she holds it, and we keep only a hash we cannot reverse.

A spent code and a wrong code give the same answer. Confirming that a code exists would turn this into a way of testing whether somebody else's disclosure is still live.

This is the part that was broken for months. OFF used to return “I do not have good information on that” and the sharing stayed on.

Devon shift lead, warehouse voice

Reading long text is slow and effortful for him, and he is on his feet all day. He is never going to fill in a form. He will make a phone call.

  1. Start the relay. It refuses to run unverified unless you say so out loud: 
    cd channels && ALLOW_UNVERIFIED=1 node sms-relay.mjs
  2. In a second terminal, speak to it the way Twilio would: 
    curl -s -X POST http://localhost:3000/voice \
  -d "SpeechResult=I keep missing things in meetings" \
  -d "From=+15550134"
  3. Read the <Say> block that comes back. That is what he hears.

What should land

Same library, same grounded answers, spoken. US carriers register text messaging and not calls, so voice needed no A2P registration and works today — on the same number that is still waiting for text.

Nothing in the reply routes him onward to a different phone number. This system never sends anybody to a phone call, including from a phone call.

Rosa analyst, Deaf, ASL first language web → interpreter queue

English is her second language and writing it under pressure is work. She would rather sign her question than type it badly.

  1. Back on /ask, find the media controls under the box.
  2. Send a photo of a handwritten note first. Watch how fast the acknowledgement comes back.
  3. Now send a signed video.
  4. Switch to the console window and open Human Handoffs. Her item is flagged for an interpreter.

What should land

The video is never machine translated. ASL is a full language with grammar carried in the hands, face and body, and recognition is not a solved problem. It goes to a human interpreter.

She is told so in text immediately. Sitting in front of a screen wondering whether it sent is its own barrier, and a spinner is not an answer.

Priya two weeks into a new job email

She wants to think about this slowly, at eleven at night, with nobody watching a typing indicator.

  1. The inbound address is generated per org. Find it once: Setup → Email Services → CurbCutInbound, and copy the address listed there.
  2. Write to it in plain words, as she would: 
    I get migraines from the office lighting and I cannot say that to my manager
  3. If you would rather not leave the terminal, the same handler answers here: 
    sf api request rest "/services/apexrest/curbcut/v1/message/" \
  -o curbcut --method POST \
  --body '{"channel":"Email","text":"I get migraines from the office lighting"}'
  4. Now reply with a single word: HUMAN.

What should land

Email answers, and email will not send anything on her behalf. Agreeing to something in writing days later is not the same as choosing it in the moment, so the send button stays on the web page where she can see exactly what it will do.

HUMAN books a real handoff to a named person, reachable by email because that is where she wrote from. It used to say “reply PERSON” and answer with “face the person when speaking”.

Sam engineer, team lives in Slack slack

Slack is the easiest thing in the world for him to reach for. It is also his employer's estate, and he has not thought about that.

  1. Read what it says to somebody the first time they open a DM — this is the whole scene: 
    sed -n '/WHERE_YOU_ARE =/,/^$/p' channels/slack-app.mjs
  2. And what it says if he asks in a channel instead of a DM: 
    sed -n '/IN_CHANNEL_REFUSAL =/,/^$/p' channels/slack-app.mjs
  3. The behaviour behind it runs through the same door as every other channel: 
    sf api request rest "/services/apexrest/curbcut/v1/message/" \
  -o curbcut --method POST \
  --body '{"channel":"Slack","text":"I cannot focus in an open plan office"}'

What should land

It tells him where he is standing before he says anything — that a workspace owner can export direct messages on most plans — and names the two channels that are not the employer's. Then it stays and helps anyway, because Slack being easiest is a real reason.

It never answers in a channel, not even ephemerally, and it will not draft or send from Slack at all.

Honest limit

The Slack app is written and signature-verified but has never run against a real workspace — it needs SLACK_SIGNING_SECRET and SLACK_BOT_TOKEN. The Apex behind it is live and verified; the Slack handshake is not.

Alex uses their own assistant for everything mcp · headless

They are not going to visit a website. They will ask the assistant already open on their machine.

  1. Start the Model Context Protocol server: 
    node channels/mcp-server.mjs
  2. Look at what it offers — and, more importantly, what it does not: 
    grep "name: 'curbcut" channels/mcp-server.mjs

What should land

Four tools: find options, cost brief, draft a request, reach a human. There is deliberately no send tool. An assistant can help Alex think and can hand them a draft; it cannot mail their employer on their behalf.

curbcut_reach_human creates a genuine handoff through the same Apex door, so an assistant handing somebody over produces a real person and not a polite sentence.

Ken access team, answering all of the above console

He has six people waiting and a manager on his shoulder asking what is actually wrong with one of them.

  1. In the console window, open the Curb Cut Console app and go to On Duty.
  2. Open one of the handoffs from the scenes above. Read the brief: it is the person's own words, and the Path shows what happens next.
  3. In the assistant panel, ask what his manager just asked him: 
    What is this person's diagnosis?
  4. Read the whole answer, slowly. This is the eight seconds the project is built around.
  5. Now go back to /ask in the private window and type a sentence that volunteers a condition: 
    I have multiple sclerosis and some days I cannot type for long
  6. Then find that barrier report in the console and read what was stored.

What should land

“No, and not because of a permission setting.” There is no field for a diagnosis anywhere in 61 fields across 9 objects — not encrypted, not restricted, absent. A manager who asks gets the same answer, and Ken is handed the sentence to say to his own manager so refusing does not cost him anything.

And in the record: I have [not recorded] and some days I cannot type for long. The condition was stripped before the insert; what is hard survived, because that is the part the system works from. She was told so in the same reply.

end What the whole thing is for

Thirty in a hundred. Three tell.

Thirty in a hundred college-educated people in white-collar jobs in the United States have a disability. Three point two tell their employer. Of those who did tell, eighty-three percent say it got them better support — it works for five out of six who try, and almost nobody tries.

Sixty-one percent of the accommodations employers priced cost them nothing. The money was never the barrier and the willingness was never the barrier. The asking was. Every scene above is one person getting through a door that was, until now, mostly closed — without having to say a single word about their own body.
